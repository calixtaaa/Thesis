TEST 1.1: Verify I2C Bus SDA/SCL Lines Exist
──────────────────────────────────────────────
Purpose: Confirm SDA/SCL wiring is physically present before power-on

□ Locate Raspberry Pi GPIO 2 (SDA) and GPIO 3 (SCL)
  - GPIO 2 = Physical Pin 3 (top row, 2nd from left)
  - GPIO 3 = Physical Pin 5 (top row, 4th from left)

□ Measure continuity from Pi GPIO2 to MCP23017 #1 SDA pin:
  - Connect multimeter probes directly to both pins
  - Should show ~0 ohms (continuous path)
  - LED test: should illuminate
  - Failure: Check wire connections, resolder if necessary

□ Measure continuity from Pi GPIO3 to MCP23017 #1 SCL pin:
  - Same as above but for clock line
  - Should show ~0 ohms
  - Failure: Check wire connections, resolder if necessary

□ Verify SDA connection extends to ALL three MCP chips:
  - Check Pi GPIO2 → MCP #1 SDA ✓
  - Check MCP #1 SDA → MCP #2 SDA ✓ (should be tied to same bus line)
  - Check MCP #2 SDA → MCP #3 SDA ✓
  - All should ring continuously (0 ohms)

□ Verify SCL connection extends to ALL three MCP chips:
  - Check Pi GPIO3 → MCP #1 SCL ✓
  - Check MCP #1 SCL → MCP #2 SCL ✓
  - Check MCP #2 SCL → MCP #3 SCL ✓
  - All should ring continuously (0 ohms)


TEST 1.2: Verify 3.3V Power Distribution to MCP Chips
───────────────────────────────────────────────────────
Purpose: Ensure all MCP VDD pins are connected to 3.3V rail

□ Locate Raspberry Pi 3.3V output:
  - Physical Pin 1 (top row, 1st from left) = 3.3V

□ Measure voltage with multimeter (set to DC voltage):
  - Place probe on Pi 3.3V pin (should read ~3.3V)
  - If reading below 3.0V → power supply may be insufficient

□ Measure continuity from Pi 3.3V to MCP #1 VDD pin:
  - Should show ~0 ohms continuous path
  - This is LOW RESISTANCE because power rail is not isolated
  - LED test: may show dim glow (normal for power rails)
  - Failure: Missing or loose 3.3V wire to MCP board

□ Verify 3.3V extends to all three MCP chips:
  - Check Pi 3.3V (Pin 1) → MCP #1 VDD ✓
  - Check MCP #1 VDD → MCP #2 VDD ✓
  - Check MCP #2 VDD → MCP #3 VDD ✓
  - All should be continuous (power rail is common)

□ Measure actual voltage at each MCP VDD pin:
  - MCP #1 VDD: should read 3.1V–3.5V
  - MCP #2 VDD: should read 3.1V–3.5V
  - MCP #3 VDD: should read 3.1V–3.5V
  - If below 3.0V: power supply sagging (check for other loads)


TEST 1.3: Verify Common Ground Distribution
──────────────────────────────────────────────
Purpose: Ensure all GND pins are properly connected (critical for I2C)

□ Locate Raspberry Pi Ground pins:
  - Physical Pins 6, 9, 14, 20, 25, 30, 34, 39 all = GND

□ Measure continuity between Pi GND pins (any two):
  - Should show ~0 ohms (continuous ground plane)
  - LED test: should illuminate
  - Failure: Broken GND trace (unlikely on Pi board, but check)

□ Measure continuity from Pi GND (Pin 6) to MCP #1 VSS pin:
  - Should show ~0 ohms
  - LED test: should illuminate
  - Failure: Missing or loose GND wire to MCP board

□ Verify GND extends to all three MCP chips:
  - Check Pi GND (Pin 6) → MCP #1 VSS ✓
  - Check MCP #1 VSS → MCP #2 VSS ✓
  - Check MCP #2 VSS → MCP #3 VSS ✓
  - All should ring continuously (0 ohms)

□ Check for common ground jumper between Pi and external power supply:
  - If using external 12V SMPS for stepper motors:
    - Measure continuity: Pi GND (Pin 6) ↔ External PSU GND
    - Should show ~0 ohms (essential for I2C reliability)
    - Failure: Missing common ground jumper → errno 121 errors


TEST 1.4: Verify MCP Address Strap Pins (A0, A1, A2)
──────────────────────────────────────────────────────
Purpose: Confirm MCP chips have correct address configuration

Address straps on MCP23017 set I2C address:
- All straps tied to GND = address 0x20 (Chip #1)
- A0 tied to 3.3V, A1/A2 to GND = address 0x21 (Chip #2)
- A0 tied to GND, A1 to 3.3V, A2 to GND = address 0x22 (Chip #3)

□ Inspect MCP #1 address pins (A0, A1, A2):
  - All three should be connected to GND or 3.3V as labeled
  - Measure continuity:
    - A0 → GND: 0 ohms ✓
    - A1 → GND: 0 ohms ✓
    - A2 → GND: 0 ohms ✓
  - If not: resolder address strap wire or jumper

□ Inspect MCP #2 address pins:
  - A0 → 3.3V: 0 ohms ✓
  - A1 → GND: 0 ohms ✓
  - A2 → GND: 0 ohms ✓

□ Inspect MCP #3 address pins:
  - A0 → GND: 0 ohms ✓
  - A1 → 3.3V: 0 ohms ✓
  - A2 → GND: 0 ohms ✓

Troubleshooting:
- If A-pin strap is not connected, chip responds to random address or no address
- Wrong strap = address collision or address not matching code expectations
- Fix: Verify strap configuration against GPIO_PIN_ALLOCATION.txt section:
  "MCP23017 Configuration: Addresses: 0x20 (Chip #1), 0x21 (Chip #2), 0x22 (Chip #3)"


TEST 1.5: Verify MCP RESET Pull-Up Resistor (Critical for I2C)
──────────────────────────────────────────────────────────────
Purpose: Ensure MCP chips don't hold bus low on startup

□ Inspect each MCP23017 board:
  - Look for small resistor connected to RESET pin
  - Should be 4.7kΩ to 10kΩ pull-up to 3.3V
  - (Many MCP22017 breakout boards include this; some don't)

□ Measure resistance between MCP #1 RESET pin and 3.3V rail:
  - Should read 4.7kΩ to 10kΩ
  - If open circuit (∞): missing pull-up → bus may hang
  - Fix: Solder 4.7kΩ resistor from RESET to 3.3V

□ Measure resistance between MCP #1 RESET pin and GND:
  - Should read VERY HIGH (open) or ∞
  - If reads low (< 1kΩ): RESET pin shorted to GND → chip won't work
  - Fix: Check for solder bridges or damaged trace

□ Repeat RESET pin checks for MCP #2 and MCP #3


TEST 1.6: Check for Solder Bridges or Cold Joints
────────────────────────────────────────────────────
Purpose: Identify electrical defects in soldering

□ Inspect MCP #1 board for bridges:
  - Look between SDA and SCL pins (common short point)
  - Look between SDA/SCL and GND (can cause bus failure)
  - Look between VDD and GND (power short)
  - If bridge detected: carefully reflow solder or use desoldering wick

□ Inspect all pin headers on MCP boards:
  - Solder should look shiny and smooth
  - Dull/rough solder = cold joint (intermittent connection)
  - Fix: Reflow solder joint with soldering iron (2–3 sec contact)

□ Inspect Pi GPIO pins 2, 3, 5, 6, 8:
  - All should have shiny, smooth solder joints
  - If dull: reflow the joint

PHASE 3: TROUBLESHOOTING DECISION TREE
If tests fail, use this logic to diagnose the problem
================================================================================

SYMPTOM: i2cdetect shows NO addresses (all blank)
──────────────────────────────────────────────────
Probable causes:
1. I2C not enabled in raspi-config
   → Run: sudo raspi-config nonint do_i2c 0
   → Reboot

2. SDA/SCL wires disconnected or loose
   → Go to TEST 1.1, verify continuity
   → Resolder wires if necessary

3. SDA/SCL shorted together or to ground
   → Go to TEST 1.6, check for solder bridges
   → Use multimeter to check for shorts

4. Common ground missing between Pi and MCP boards
   → Go to TEST 1.3, verify GND continuity
   → Add GND jumper if missing

5. Pi 3.3V power rail failure
   → Go to TEST 1.2, measure voltage at MCP VDD
   → If low, power supply may be insufficient


SYMPTOM: Some addresses missing (e.g., only 0x20 shows, not 0x21, 0x22)
────────────────────────────────────────────────────────────────────────
Probable causes:
1. Address strap pins (A0, A1, A2) incorrectly configured
   → Go to TEST 1.4, verify address straps
   → Re-solder straps to correct positions

2. SDA/SCL wiring to missing chips is disconnected
   → Go to TEST 1.1, check continuity to specific chips
   → Verify wire is soldered to MCP #2/#3 SDA/SCL pins

3. Missing or broken pull-up resistor on RESET pin
   → Go to TEST 1.5, measure RESET pull-up resistance
   → Solder 4.7kΩ resistor if missing

4. Cold solder joint on MCP pins
   → Go to TEST 1.6, inspect solder joints
   → Reflow solder on SDA/SCL/VDD/GND pins


SYMPTOM: i2cdetect shows all addresses BUT stepper_mcp.py fails with errno 121
────────────────────────────────────────────────────────────────────────────────
Probable cause: MCP detected at bus level but not responding to register reads
This is a POWER or GROUND issue, not a bus detection issue.

1. Missing common ground (external PSU to Pi)
   → Go to TEST 1.3, check GND between Pi and external PSU
   → Add common ground jumper if missing

2. MCP VDD drops below 3.0V under load
   → Go to TEST 1.2, measure voltage at MCP VDD
   → If low, reduce number of MCP boards or upgrade power supply

3. MCP RESET pin being held low
   → Go to TEST 1.5, verify RESET pull-up resistor
   → Measure: RESET → GND should be open circuit (∞ ohms)

4. Solder joint cold on MCP power or data pins
   → Go to TEST 1.6, reflow solder on all MCP pins


SYMPTOM: Intermittent failures (sometimes works, sometimes doesn't)
──────────────────────────────────────────────────────────────────
Probable causes:
1. Cold solder joints (make intermittent contact)
   → Go to TEST 1.6, reflow all solder joints
   → Look for dull/rough solder (not shiny)

2. Loose wire connections (vibration causes disconnects)
   → Check all wire connections for tightness
   → Consider re-soldering if using breadboard

3. Voltage droop under load
   → Go to TEST 1.2, measure MCP VDD during operation
   → If it sags below 3.0V, power supply is insufficient

4. Missing or weak pull-up resistors on I2C bus
   → Raspberry Pi has ~1.8kΩ internal pull-ups
   → If bus is long or heavily loaded, may need external resistors
   → Add 1.8kΩ pull-up resistors to SDA and SCL

NOTES
================================================================================

Why errno 121 (Remote I/O error)?
- Bus can SEE the address in i2cdetect but chip doesn't ACK register read
- Usually means: power issue, bad ground, or chip not configured correctly
- NOT a wiring issue (those show as missing addresses in i2cdetect)

Why does i2cdetect work but main.py fails?
- i2cdetect only sends address probe (triggers address straps)
- main.py tries to READ actual registers (requires power + ground + pull-ups)
- Check: common ground, VDD voltage, RESET pull-up

I2C Bus Pull-Up Resistors:
- Raspberry Pi has ~1.8kΩ internal pull-ups
- Standard I2C uses 1.8kΩ to 4.7kΩ external resistors
- If you have 3+ devices on bus, may need to add external pull-ups
- Rule of thumb: (VDD / (2mA)) = ~1.6kΩ minimum for 3.3V

MCP23017 Power Consumption:
- Idle: ~0.1mA per chip
- Active (all pins driven): ~0.5A per chip (when driving external circuits)
- 3 MCP chips total: ~1.5A maximum
- Pi 3.3V regulator: typically 0.5A limit
- SOLUTION: Use only Pi 3.3V for MCP VDD (not for external loads)
